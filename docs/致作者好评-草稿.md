# moss-nano-port 好评(草稿 · 待 Nija 过目后发布)

## 中文版(GitHub Discussion / Issue)

**标题:多謝!呢個係我用過最好嘅開源粵語 TTS —— 同一個 2.2GB 大模型嘅實測對比**

多謝 @typangaa 整咗 moss-nano-port。我喺兩部機上試咗(**Arch Linux x86_64 + 一部 Android 平板嘅 Debian 13 aarch64 chroot**),
兩邊都跑得順,而且係 **CPU-only、零 GPU**。

**令我驚訝嘅地方:**

1. **效果好過我哋自己用嘅 2.2GB 大模型**
   我哋原本用一個 1.7B 參數、GGUF q8、2.2GB、**要 GPU** 嘅粵語 TTS。
   你哋個 **729MB、0.1B、CPU-only** 嘅模型,聽感上**贏咗**。
   ⇒ 呢個說服咗我:**架構同訓練數據質素,比 parameter 數重要。**

2. **真係好易裝**
   `pip install moss-nano-port` 就搞掂,aarch64 有預編譯輪子
   (`canto-hk-g2p` 有 `cp38-abi3-manylinux_2_17_aarch64`、`onnxruntime` 有 `cp313-manylinux_2_28_aarch64`),
   **唔使自己 compile Rust**。Android chroot 都直接裝得。

3. **合成速度合理**(平板 aarch64、11 字 ≈6 秒;x86_64 快好多)

**兩個小建議(bug report 級,唔係投訴):**

1. **HF 緩存係符號連結,ONNX 會拒載。**
   ```text
   OnnxRuntimeError: External data path validation failed ... escapes model directory.
   resolved path: .../blobs/b0/b0...   allowed directory: .../blobs/54
   ```
   ⇒ 我哋要 `cp -rL` 實體化先得。**建議 README 提一句**,或者喺下載時自動實體化。

2. **`--quality best_of_n` 喺 aarch64 上要 `faster-whisper`/`ctranslate2`/`av` 嘅輪子**,嗰幾個冇 aarch64 版。
   ⇒ 如果可以,希望加個「唔用 reranker 嘅降級」或者純 ONNX 嘅品質模式。
   (明白呢個唔係核心功能,只係想講聲。)

**最後想講:**

你喺 README 老實講「**單一 default voice,冇 voice 揀**」——
呢種**唔呃人嘅寫法**好難得,多謝你冇吹到天花龍鳳。
效果本身已經足夠說服人。

如果你日後想加 **voice cloning / 多音色**(哪怕係 experimental),
我哋一定第一個試 —— 因為底子已經好靚。

再次多謝!🙏

## English version

**Title: Thank you — this is the best open-source Cantonese TTS I've used (beats our 2.2GB model in A/B)**

Thanks @typangaa for moss-nano-port. I tested it on two machines
(**Arch Linux x86_64** and **a Debian 13 aarch64 chroot on an Android tablet**) —
both work, and it's **CPU-only, zero GPU**.

**What surprised me:**

1. **It sounds better than our own 2.2GB model.**
   We were using a 1.7B-param, GGUF q8, 2.2GB, **GPU-required** Cantonese TTS.
   Your **729MB, 0.1B, CPU-only** model wins on listening tests.
   ⇒ This convinced me that **architecture + training data quality matter more than parameter count.**

2. **Installation just works.**
   `pip install moss-nano-port`, with prebuilt aarch64 wheels
   (`canto-hk-g2p` ships `cp38-abi3-manylinux_2_17_aarch64`; `onnxruntime` has `cp313-manylinux_2_28_aarch64`) —
   **no Rust compilation needed**. Even works inside an Android chroot.

3. **Reasonable synthesis speed** (~6s for 11 chars on aarch64; much faster on x86_64).

**Two small suggestions (bug-report level, not complaints):**

1. **The HF cache uses symlinks, and ONNX refuses to load them.**
   ⇒ We had to `cp -rL` to materialize. **Worth a README note**, or auto-materialize on download.

2. **`--quality best_of_n` needs `faster-whisper`/`ctranslate2`/`av` wheels that have no aarch64 builds.**
   ⇒ A fallback / pure-ONNX quality mode would be nice.

**One last thing:**

You honestly state in the README that it's a **"single default voice, no voice selection"** —
that kind of **non-overselling documentation** is rare and appreciated.

If you ever add **voice cloning / multi-voice** (even experimental),
we'll be the first to try it — the foundation is already excellent.

Thanks again!
